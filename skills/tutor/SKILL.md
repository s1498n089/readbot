# tutor

陪使用者**唸一本已經數位化／翻譯好的書**：回答使用者對某章的問題、把難懂的點講通，並把學到的重點**收進該章的 note**。
這是 `digitize-book` 的下游夥伴——digitize-book 把書**做出來**，tutor 陪使用者**讀進去**、並讓筆記**愈讀愈厚**。

> 🎯 **只增補 note、不碰本文。** 翻譯／數位化的本文是 digitize-book 的產物、要保持忠實；tutor 只在**該章 note** 裡加「補充」。心智圖不必另做——看板的「心智圖」檢視會照 note 的**結構標記**（`## x.y` 小節、`**重點**`／`**關鍵詞**` 等，見 §4）把筆記鏡射成樹，補完 note 重刷就長出來。

## 0. 取得 plugin 根目錄
系統會在開頭給「**Base directory for this skill**」（= `<plugin>/skills/tutor`）。**plugin 根 = 該 base 的上兩層**（`<base>/../..`），解析成絕對路徑 `<PLUGIN_DIR>`，需要跑包內 python 時帶 `--project "<PLUGIN_DIR>"`。`book/` 相對使用者目前 cwd；產物只在 `book/<書>/output/`、過程檔進 `tmp/`，**勿污染 project root**。

## 1. 確認要陪讀哪本、哪一章
- **哪本書／哪一章** → 對到 `book/<書>/`。先讀 `config.json`（語言、格式 md/ipynb）與 `progress.md`（哪些章已做好），不夠再問使用者。
- **前提檢查**：該章要已有產物——本文 `output/<語言>/<fmt>/ch<n>/ch<n>.<ext>` 與 note `.../note/ch<n>/ch<n>.<ext>`。**還沒有 → 先請使用者用 `/readbot:digitize-book` 做那一章**（tutor 不負責產出本文）。

## 2. 載入該章上下文（教對的前提）
用 **Read** 把該章**本文＋note**讀進來當依據——手上有完整章節脈絡，才能講對、才不會跟書打架。
- 本文：`book/<書>/output/<語言>/<fmt>/ch<n>/ch<n>.<ext>`
- 筆記：`book/<書>/output/<語言>/<fmt>/note/ch<n>/ch<n>.<ext>`
- 使用者問到某個詞／某段時，**先回本文找到原句**（必要時 `grep` 該章 ipynb/md）再解釋，確保講的跟書一致；書上沒有、屬延伸知識，就明說是補充。

## 3. 陪讀：用「白話打痛點」把難懂處講通
回答使用者的問題時，照 digitize-book §7 的精神（這正是本 plugin 最有價值的地方）：
- **站在小白視角**：這段真正想解決什麼問題？最容易卡在哪、誤解什麼？
- **用具體例子／走一遍流程／一個小數字／一個類比**把抽象講成人話；能畫流程就畫（純文字箭頭圖也好）。
- **誠實**：不確定就說不確定、回去翻本文或查證；**英文較弱的讀者無法自己抓錯**，寧可標註疑點，別自信地講錯。
- 一次講一個點、講到懂，再問使用者要不要往下。

## 4. 把重點收進該章 note（核心動作）
使用者說「收進筆記／整理重點」時（或 Claude 判斷這點值得記、之後會想複習時），把它**言簡意賅**寫進**該章 note**：
- **先讀使用者專案根的 `note-style.md`（若有）→ 照它的口味與切角寫**（§A），並沿用它列的**結構標記**（§B：`**重點**`／`**白話打痛點**`／`**關鍵詞**`／條列／分隔符——心智圖靠這套解析）。沒有 `note-style.md` 就用下面的預設。
- **言簡意賅**：濃縮成「可複習的筆記」，**別把整段對話貼進去**。建議結構＝**重點一句 ＋ 必要的白話／類比 ＋ 雙語關鍵詞**（關鍵詞也是日後學習小卡的素材）。
- **落在「該重點在書裡所屬的小節」**（重要）：先回**本文**找出這個問題的重點出現在哪一節（`### x.y`），note 就用 `## x.y <小節標題>` 收在那裡——
  - **該節已有 note → 併進去**（補在既有內容後、或相關段落旁），不另開一塊。
  - **該節還沒 note → 在「正確節次順序」的位置新建** `## x.y <小節標題>`（例：1.4 與 1.4.5 之間補 1.4.1）。
  - **別用泛泛的「## 補充」另立區塊**：對齊真實節次，心智圖才會把它掛在對的小節下、複習時也按書的節次找得到。（例：問「Brotli／JS bundle 是什麼」→ 本文落在 §1.4.1 → 收進 `## 1.4.1`，而不是 `## 補充`。）
- **跟本文同格式寫**：
  - **ipynb** → 先 **Read** 該 note（看 `<cell id="...">`），再用 **NotebookEdit** 在相關 cell 後 `insert` 一個 **markdown cell**（`cell_type: markdown`）。
  - **md** → 在相關段落後插入一段。
- **原子安全**：NotebookEdit 是單 cell 操作、天然安全；若是手寫 ipynb JSON 則先 `.tmp` 再 `os.replace`。
- ⚠️ **marked.js 核心版不吃 markdown 註腳**（`[^1]` 會原樣噴出、爆版）：要附註用「（注 N）」＋該段後面 blockquote `> **注 N**：…`。表格、`$ $`／`$$ $$` 數學可用。
- 🚫 **絕不改本文**：只在 note 增補；翻譯／數位化本文一律不動。

## 5. 渲染驗收（補完就驗，別插完就算）
跟 digitize-book §6 對等——確認在看板上真的長對：
- 開 `http://localhost:5050`，在頁面 context 跑看板的全域函式 `renderIpynb(doc, base)`（`doc`＝該 note 內容、`base`＝該章目錄），驗產出的 DOM：`[^` 註腳（應 0）、漏出的 `$`（應 0，數學都被 KaTeX 接走）、cell／段落數量有沒有如預期多出剛補的那塊、關鍵字（剛補的詞）有沒有出現。
- 沒有 CDP／看板沒開 → 至少 `grep` 該 note 有沒有 marked 不吃的語法（`[^`），並請使用者重刷看一眼。

## 6. 收尾
- **心智圖自動更新**：不必另做。請使用者重刷看板、切到該章「心智圖」檢視，剛補的關鍵詞就會出現。
- **（選配）記一筆**：可在 `book/<書>/progress.md` 補一句口語紀錄（例：「ch1 note 補了『JS bundle／Brotli 壓縮』」），讓下次接得上。
- 收工前確認沒有暫存檔留在 project root。

## 注意
- **與 digitize-book 分工**：digitize-book＝產出本文／筆記／插圖（重活、長時間）；tutor＝陪讀＋把學到的補進既有 note（輕量、可隨時來一段）。需要新的一章還沒做 → 回 digitize-book。
- **路徑與慣例**沿用 digitize-book：plugin 根用 base 的上兩層推、note 路徑、ipynb 手組 JSON、marked 註腳坑、原子寫入、渲染驗收——同一套，不另立規矩。
- 所有包內 python 走 `uv run --project "<PLUGIN_DIR>"`；過程檔只進 `tmp/`、產物只進 `book/<書>/output/`。
